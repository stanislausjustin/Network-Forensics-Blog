The Traffic Analyst's Toolkit

Week 6 Session

This week was all about looking past the "what" and into the "how" of network communication. Traffic analysis allows us to identify scanning or exfiltration even when encryption hides the payload.

The Week 6 Lab

I performed traffic analysis on 3 PCAP files today to distinguish normal vs. abnormal traffic patterns.

Lab Overview

Activity: Performed hands-on analysis of three network captures to distinguish normal vs. abnormal traffic.

Sample 1 Analysis

Focused on a 2-minute capture featuring 608 packets. The analysis revealed:

  • Duration: Approximately 119.85 seconds (2 minutes)
  • Packet Count: 608 packets
  • File Size: 1.6 MB
  • Average Packet Size: 2,716 bytes
  • Data Rate: 13 kbps

Protocol Analysis

Dominant protocols included:

  • SMB (Server Message Block): Windows file sharing protocol
  • NBSS (NetBIOS Session Service): Windows service discovery
  • TLS: Secure session establishment

Conclusion: Standard Windows-based LAN file sharing and secure session establishment. No anomalies or scanning patterns were detected. The traffic represents legitimate internal communication between two hosts in a virtualized Windows LAN environment.

Sample 2 Analysis

Investigated a low-traffic 7-minute capture with the following characteristics:

  • Duration: Approximately 436.99 seconds (7 minutes)
  • Packet Count: 82 packets
  • File Size: 11 kB
  • Average Packet Size: 119.91 bytes
  • Data Rate: 180 bits per second

Traffic Composition

The capture consisted entirely of:

  • ARP (Address Resolution Protocol): Host discovery and IP-to-MAC address resolution
  • ICMP (Internet Control Message Protocol): Echo requests and replies (ping operations)

Conclusion: A very quiet capture, likely just basic heartbeats or connectivity checks. The small packet sizes and Ethernet encapsulation suggest local diagnostic or connectivity testing within a virtualized environment. This represents normal network setup and troubleshooting activity.

Sample 3 Analysis

Observed a flow beginning with TCP and SMB communications, typical of resource discovery:

  • Duration: Approximately 51.06 seconds
  • Packet Count: 740 packets
  • File Size: 1.6 MB
  • Average Packet Size: 2,233 bytes
  • Data Rate: 258 kbps

Traffic Flow

The capture showed a clear progression:

  1. Initial Phase: TCP exchanges and SMB (Server Message Block) communications over NBSS, typical of Windows-based file sharing and service discovery
  2. Mid-Session: TLS handshake packets appeared between hosts, showing the establishment of a secure connection
  3. Throughout: ICMP packets suggesting connectivity testing or keep-alive messages

Conclusion: Caught a clear transition from standard SMB discovery to a secure TLS session. The presence of TLS handshakes midway through the capture likely represented authentication or encrypted data transfer between hosts. Overall, the capture reflects normal Windows LAN behavior with legitimate internal network activity.

Key Insights

  • Sample 1: Saw a lot of SMB and TLS traffic—classic Windows LAN behavior.
  • Sample 2: A very quiet capture, likely just basic heartbeats or connectivity checks.
  • Sample 3: Caught a clear transition from standard SMB discovery to a secure TLS session.

Tools Used

For this analysis, I utilized:

  • capinfos: For extracting PCAP file metadata
  • Wireshark: For protocol analysis and traffic visualization
  • tshark: For command-line packet analysis and filtering
