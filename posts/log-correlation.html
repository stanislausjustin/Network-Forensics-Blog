Log Correlation

Week 9 Session

In log correlation we need to make sure that timestamps is correct and the integrity of the logs is not changed. For skill, you need to understand the context, topology (in network), and has deep understanding for services are running/investigating. The expected output from log correlation basically is a picture of when the incident occurred so that it can reveal what happened precisely.

Key Principles

Timestamp Accuracy: Ensuring all log timestamps are correct and synchronized across systems.

Log Integrity: Verifying that logs have not been altered or tampered with.

Context Understanding: Knowing the network topology and services being investigated.

What is Log Correlation?

Log correlation is the process of analyzing and correlating log data from multiple sources to identify patterns, anomalies, and security incidents. It involves collecting logs from various systems, normalizing them into a standardized format, and analyzing them to create a comprehensive picture of network activity and security events.

What is Most Important in Log Correlation Activity?

The most important activity is the centralization and normalization of all logs into a standardized format with corrected timestamps.

This process involves:

  • Centralization: Collecting logs from all sources (firewalls, servers, switches, routers, IDS/IPS, applications) into a single location
  • Normalization: Converting logs from different formats into a standardized structure that can be easily analyzed
  • Timestamp Correction: Ensuring all timestamps are synchronized and accurate, accounting for time zones and clock drift

Without proper centralization and normalization, it becomes nearly impossible to correlate events across different systems and create an accurate timeline of incidents.

What Skills Do You Need to Perform Log Correlation?

The required skill is security incident investigation and rule development to analyze the normalized data and create custom detection rules.

Key skills include:

  • Security Incident Investigation: Understanding attack patterns, indicators of compromise, and how to trace security events
  • Rule Development: Creating custom detection rules and queries to identify suspicious patterns
  • Network Topology Understanding: Knowing how devices are connected and how traffic flows through the network
  • Service Knowledge: Deep understanding of the services running on the network and their normal behavior
  • Context Analysis: Ability to understand the context of events and how they relate to each other

What Are Expected Outputs from Log Correlation?

Expected outputs are actionable security intelligence and clear visualization of threats, identifying compromised endpoints, network misconfigurations, and covert communication channels.

Specifically, log correlation should produce:

  • Incident Timeline: A clear picture of when the incident occurred, showing the sequence of events
  • Threat Identification: Detection of security threats, attacks, and anomalies
  • Compromised Endpoints: Identification of systems that have been breached or compromised
  • Network Misconfigurations: Discovery of configuration errors that could lead to security vulnerabilities
  • Covert Communication Channels: Detection of hidden or unauthorized communication channels
  • Actionable Intelligence: Information that can be used to respond to and mitigate security incidents

The Correlation Process

The log correlation process typically follows these steps:

  1. Collection: Gather logs from all relevant sources
  2. Normalization: Convert logs to a standardized format
  3. Timestamp Correction: Synchronize all timestamps
  4. Enrichment: Add context and additional information
  5. Correlation: Identify relationships and patterns across logs
  6. Analysis: Investigate correlated events
  7. Visualization: Create visual representations of findings
  8. Reporting: Document findings and recommendations

Best Practices

  • Maintain log integrity through hashing and secure storage
  • Use synchronized time sources (NTP) across all systems
  • Store logs in a centralized SIEM (Security Information and Event Management) system
  • Develop and maintain custom correlation rules
  • Regularly review and update correlation logic
  • Document network topology and service dependencies
  • Create visual dashboards for quick threat identification
